About the data

These are NYC Taxi and Limousine Commission yellow taxi trip records for January 2024, with a location lookup and the game's teaching changes. row_id and loaded_at describe the load, not the trip. Location 264 means Unknown (zone N/A); 265 means Outside of NYC.

trips_raw
  • row_id: Unique identifier for a physical row in the feed; load metadata, not a trip key.
  • vendor_id: Provider that recorded the trip.
  • pickup_at: Pick-up date and time in local time, without a time zone.
  • dropoff_at: Drop-off date and time in local time, without a time zone.
  • passenger_count: Reported number of passengers.
  • trip_distance: Reported trip distance in miles.
  • pu_location_id: Pick-up location id, matched to zones.location_id.
  • do_location_id: Drop-off location id, matched to zones.location_id.
  • payment_type: Code for the reported payment method.
  • fare_amount: Metered fare amount in dollars.
  • tip_amount: Recorded tip amount in dollars.
  • total_amount: Reported total trip amount in dollars.
  • loaded_at: When the physical row was loaded; load metadata, not a trip key.
zones
  • location_id: Location id used to match a trip location.
  • borough: Borough reported for the location.
  • zone: Name of the location.
  • service_zone: Service area reported for the location.

Source: NYC TLC trip records and Yellow taxi data dictionary (PDF). The game renames columns, for example tpep_pickup_datetime becomes pickup_at, and adds row_id and loaded_at. Use the game's column list above when writing your SQL.

Floor 1: The double shift

Cleared

The feed came in twice

The depot dashboard is overstating revenue because one delivery arrived twice. trips_raw holds every physical row in the incoming feed, including both copies, and zones names the locations. Keep one whole row per trip so the morning report counts each ride once.

SQL refresher

A query in steps: WITH

WITH names a query result so the next step can read it. The final SELECT returns your answer. These steps are one query; you do not need to save a table.

WITH rides(id) AS (VALUES (1), (2))
SELECT count(*) AS rides FROM rides;
A key, grain and repeated groups

Grain means what one row represents. A key is the set of columns that identifies one item at that grain. GROUP BY collects rows with the same key; HAVING filters the groups after counting. DISTINCT compares only the columns you select.

WITH deliveries(ride, fare) AS (VALUES (1, 12), (1, 12), (2, 18))
SELECT ride, fare, count(*) FROM deliveries
GROUP BY ride, fare HAVING count(*) > 1;
Keep a whole row from each group

ROW_NUMBER numbers rows inside each PARTITION BY group. ORDER BY chooses which copy comes first. Put the numbered rows in a CTE, then use WHERE rn = 1 in the final SELECT to keep one whole row per group. Leave rn out of the answer.

WITH deliveries(ride, "copy") AS (VALUES (1, 1), (1, 2), (2, 1)),
ranked AS (SELECT *, row_number() OVER (PARTITION BY ride ORDER BY "copy") AS rn FROM deliveries)
SELECT ride, "copy" FROM ranked WHERE rn = 1;
What DISTINCT compares

DISTINCT compares only the selected columns. Two loads of one ride can have different copy numbers, so selecting every column keeps both. Selecting just ride gives one ride value. This differs from keeping one complete row with ROW_NUMBER.

WITH loads(ride, "copy") AS (VALUES (1, 1), (1, 2))
SELECT DISTINCT ride FROM loads;
Round a displayed amount

ROUND(value, 2) displays an amount to two decimal places. Round a total for presentation after calculating it; do not change the source amounts while choosing which trips to keep.

WITH amounts(total) AS (VALUES (1.105), (2.50))
SELECT round(total, 2) AS cents FROM amounts;
Convert a value to a type

CAST converts a value to the requested type. A timestamp literal also supplies a type for its written value. Compare values with matching types when checking dates and times.

SELECT CAST('2024-01-01' AS TIMESTAMP)
AS started_at;

Why DISTINCT finds nothing

SELECT DISTINCT removes rows that are equal in every column. The second copies are not equal: each one has a new row_id and a later loaded_at. So DISTINCT removes nothing.

To keep one whole row per trip, number the rows inside each trip-key group and keep row 1. Review the WITH and ROW_NUMBER refresher.

Lv 2 · How the check works

A row can be a copy even when some columns differ. Columns added by the load, like row_id and loaded_at, say how the row arrived. They do not say which trip it is.

FROM (SELECT DISTINCT * FROM trips_raw);  -- still 7,345

Choose a trip key

A duplicate is defined by a key you choose: the columns that together name one trip. Two rows with the same key are the same trip.

Lv 2 · How the check works

In this game the trip key is vendor_id, pickup_at, dropoff_at, pu_location_id, do_location_id and total_amount. In the full January file, this key has no duplicates.

The check: count the rows, then count the distinct keys. If the two counts differ, the table has copies.

SELECT count(*) AS trips

Floor 2: Nowhere zones

Cleared

Trips to nowhere

The depot needs to report where every trip started and ended, including trips whose locations cannot be matched. trips holds 7,171 trips with rerun copies already removed; zones is the location lookup. Keeping unmatched trips in the report prevents an incomplete picture of service and revenue.

SQL refresher

A query in steps: WITH

WITH names a query result so the next step can read it. The final SELECT returns your answer. These steps are one query; you do not need to save a table.

WITH rides(id) AS (VALUES (1), (2))
SELECT count(*) AS rides FROM rides;
Keep unmatched rows with LEFT JOIN

A JOIN matches keys between tables. A LEFT JOIN keeps every row on the left and puts NULL in the right columns when there is no match. Aliases such as r and z name the two table copies. Joining twice lets you look up two locations.

WITH rides(id, place) AS (VALUES (1, 10), (2, 99)),
places(id, name) AS (VALUES (10, 'Depot'))
SELECT r.id, z.name FROM rides r
LEFT JOIN places z ON z.id = r.place;
Label the first matching condition

CASE tests WHEN conditions in order: the first true branch wins. Here 1 meets both conditions but gets first; 2 gets second, and 3 reaches ELSE. In an answer without ELSE, rows that match no branch get NULL. Test missing values with IS NULL.

WITH examples(n) AS (VALUES (1), (2), (3))
SELECT n, CASE WHEN n < 2 THEN 'first'
WHEN n < 3 THEN 'second' ELSE 'other' END AS label
FROM examples;
Count the joined result

COUNT(*) checks that a join kept the expected number of rows. GROUP BY makes one group per label; HAVING can filter those groups. Use a WITH step to name the result you want to count.

WITH labels(flag) AS (VALUES ('known'), ('missing'))
SELECT flag, count(*) FROM labels GROUP BY flag
HAVING count(*) > 0;

Three kinds of nowhere

  • Zone 265 is "Outside of NYC". It is a real place, outside the zone map.
  • Some drop-off ids are 0 or NULL. They match nothing in the lookup.

Lv 2 · How the check works

110 trips touch zone 264, and 74 touch zone 265. These are real TLC rows. 25 trips have a drop-off id that matches nothing: 15 are 0 and 10 are NULL. These are planted for the game.

SELECT do_location_id, count(*) AS trips
FROM trips
WHERE do_location_id IS NULL
   OR do_location_id NOT IN (SELECT location_id FROM zones)
GROUP BY do_location_id;

A join can drop rows

An inner join keeps only rows that match on both sides. The trips with no matching drop-off zone disappear, and nothing warns you.

Lv 2 · How the check works

With an inner join on both ids, 7,171 trips become 7,146. A LEFT JOIN keeps every trip and puts NULL where there is no match.

An anti-join (a LEFT JOIN where the lookup side IS NULL) lists the rows that match nothing. It cannot find zone 264, because 264 is in the lookup.

SELECT count(*) FROM trips t
JOIN zones pz ON pz.location_id = t.pu_location_id
JOIN zones dz ON dz.location_id = t.do_location_id;  -- 7,146

SELECT t.row_id, t.do_location_id
FROM trips t
LEFT JOIN zones dz ON dz.location_id = t.do_location_id
WHERE dz.location_id IS NULL;  -- the 25 that match nothing

The order matters: test 'unmatched' first.

Floor 3: Impossible rides

Cleared

Impossible rides

The depot must explain rides with impossible measurements before using them in a report. trips holds 7,171 trips with zone names and zone_flag; zones is the location lookup. Separating questionable rows with a reason preserves the evidence and leaves a clean report that reconciles to the input.

SQL refresher

A query in steps: WITH

WITH names a query result so the next step can read it. The final SELECT returns your answer. These steps are one query; you do not need to save a table.

WITH rides(id) AS (VALUES (1), (2))
SELECT count(*) AS rides FROM rides;
Filter ranges and combine conditions

WHERE keeps rows whose condition is true. Compare values with <, >= and =; use AND when both conditions must hold and OR when either may hold. A timestamp range with an inclusive start and exclusive end includes the whole final day.

WITH rides(fare) AS (VALUES (-2), (10))
SELECT * FROM rides WHERE fare < 0;
WITH rides(started_at) AS (VALUES (TIMESTAMP '2024-03-01'))
SELECT * FROM rides WHERE started_at < TIMESTAMP '2024-03-01'
OR started_at >= TIMESTAMP '2024-04-01';
Choose the first reason

CASE tests WHEN conditions in order: the first true branch wins. Here 1 meets both conditions but gets first; 2 gets second, and 3 reaches ELSE. In an answer without ELSE, rows that match no branch get NULL. Test missing values with IS NULL.

WITH examples(n) AS (VALUES (1), (2), (3))
SELECT n, CASE WHEN n < 2 THEN 'first'
WHEN n < 3 THEN 'second' ELSE 'other' END AS label
FROM examples;
Keep every trip and explain its status

Return clean and bad trips together. A NULL reason means the trip is clean; a non-NULL reason records the first rule it breaks. COUNT(*) checks that every trip stays, and GROUP BY with HAVING can reveal repeated ids.

WITH checked(id, reason) AS (VALUES (1, 'negative'), (2, NULL))
SELECT * FROM checked;
Check counts by reason

COUNT(*) counts every row in each group. GROUP BY reason separates the labels; HAVING filters groups after counting. The clean count plus the quarantined count must equal the input count.

WITH checked(reason) AS (VALUES ('negative'), ('negative'), (NULL))
SELECT reason, count(*) FROM checked
GROUP BY reason HAVING count(*) > 0;
Stack results with UNION ALL

UNION ALL stacks rows from queries with matching columns and types. It keeps repeated rows, so the same trip in two branches appears twice. Keep the rule branches exclusive when using it to explain trip reasons.

WITH first_day(id) AS (VALUES (1)), second_day(id) AS (VALUES (2))
SELECT * FROM first_day
UNION ALL SELECT * FROM second_day;
Count rows that meet a condition

FILTER (WHERE ...) applies a condition to one aggregate without removing rows from the whole query. COUNT(*) still gives the total; the filtered count gives only the rows matching its condition.

WITH rides(fare) AS (VALUES (-2), (10))
SELECT count(*) FILTER (WHERE fare < 0) AS negative,
count(*) AS total FROM rides;
Convert a value to a type

CAST converts a value to the requested type. A timestamp literal also supplies a type for its written value. Compare values with matching types when checking dates and times.

SELECT CAST('2024-01-01' AS TIMESTAMP)
AS started_at;

SELECT
  count(*) FILTER (WHERE fare_amount < 0) AS negative_fare,
  count(*) FILTER (WHERE dropoff_at < pickup_at) AS time_travel,
  count(*) FILTER (WHERE pickup_at < TIMESTAMP '2024-01-01'
